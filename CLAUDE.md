# Бортом к борту — цифровой прототип настольной игры

Браузерная версия студенческой настольной игры для тестов правил и баланса. ТЗ — `docs/TZ.md`, ход работы — `docs/PROGRESS.md`, текущая задача — файл в `docs/tasks/`, который назовёт пользователь.

## Как работать

- **В начале сессии:** прочитай файл задачи из `docs/tasks/`, `docs/PROGRESS.md` и `git log --oneline -15`. Из `docs/TZ.md` читай только нужные разделы.
- Помощников (Explore, Plan и другие субагенты) не запускай, если файлы названы в задаче — читай их сам. Субагент — только когда нужно обойти много незнакомых файлов.
- **Объём:** делай только то, что в файле задачи. Новые идеи — в «Идеи на потом» в `docs/PROGRESS.md`.
- **Правила игры:** не меняй и не додумывай. Неясность — в `QUESTIONS.md` и вопрос пользователю.
- **Шаги:** один шаг плана — один коммит. После каждого шага только `npm run typecheck` — остальное проверяет CI на GitHub.
- **В конце задачи:**
  1. прогони все проверки из «Готово, когда» файла задачи;
  2. обнови `docs/PROGRESS.md` честно: что сделано, что нет и почему;
  3. закоммить, push, PR в main через `gh pr create`;
  4. отчёт: таблица «требование → сделано / не сделано → доказательство» (вывод команды, путь к скриншоту). Без доказательства пункт считается не сделанным.
- **IMPORTANT: не пиши «готово», пока не увидел вывод проверки сам.** Не подгоняй тест под код: если тест кажется неверным — скажи пользователю.
- **Если контекст заканчивается:** закоммить рабочее состояние, запиши в PROGRESS.md, что осталось.
- **Перед необратимыми действиями** (force push, удаление веток или данных) — спроси пользователя.

## Решения проекта

- Движок `src/engine/` — чистые функции без React и Node API: тот же код в браузере, на сервере и в симуляциях.
- Скрытая информация режется в `viewFor`/`eventsFor` на сервере, а не прячется в интерфейсе. Новые поля событий проходят через `eventsFor`; тест на утечки в `tests/view.test.ts` и `tests/server.test.ts` расширяй.
- Случайность — только seeded RNG из `src/engine/rng.ts`. `npm run sim -- --games 3000 --seed 1` должен давать Пираты 46,5 %.
- Числа и тексты карт — только в `data/game-data.json`, не в коде.
- Анимации: эталон — `docs/mockups/anim/level1/` (`anim-demo.html` + модули `*.js`). **Перед любой задачей про анимации прочитай `docs/mockups/anim/level1/PORTING.md`.** Переноси код эталона, не придумывай заново. Не читай `data.js` и `scenes.js` целиком (это данные в одну строку). Проверка планировщика — `validate.cjs` на дампе `scripts/dump-fx-events.ts`; кадры эталона — `capture.mjs`. Слой анимаций не блокирует ввод. Анимация выбирается по событиям и `fx`, не по названию карты. Кнопки и проверки «можно ли» — по настоящему состоянию, планшеты — по отображаемому. Только свои SVG/CSS, без кадров из фильмов.
Перед любой задачей про анимации прочитай PORTING.md и docs/mockups/anim/RULES.md. Эталон задаёт вид и тайминги; способ отрисовки — по RULES.md
- Пользователь не программист и проверяет работу на сайте и по скриншотам.

## Windows (у пользователя)

- PowerShell. Не используй `Start-Process`, ручную проверку портов и `&&` в командах для пользователя.
- Имена файлов не должны отличаться только регистром. Сервер e2e слушает `127.0.0.1`, не `localhost`.

## Язык

- Общение и интерфейс — на русском. Код, имена и коммиты — на английском.

## Команды

- `npm ci` — установка (Node.js 22). `npm run dev` — сайт локально.
- `npm test` — Vitest; один файл: `npx vitest run tests/<file>.test.ts`.
- `npm run typecheck`, `npm run build`, `npm run build:server`.
- `npm run sim -- --games 3000 --seed 1` — баланс (Пираты 46,5 %).
- `npm run e2e` — Playwright; скриншоты — в папку, которую назовёт задача.
- `npm run lan` — игра по Wi-Fi. Развёртывание — `DEPLOY.md`.
- CI: `.github/workflows/pages.yml` — проверки на каждый PR, выкладка после слияния в `main`.
