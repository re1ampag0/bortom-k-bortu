# Бортом к борту — цифровой прототип настольной игры

Браузерная версия студенческой настольной игры для тестов правил и баланса. Полное ТЗ — `docs/TZ.md`, ход работы — `docs/PROGRESS.md`.

## Как работать

- **В начале сессии:** прочитай `docs/PROGRESS.md` и `git log --oneline -15`. Из `docs/TZ.md` читай только разделы, нужные текущему этапу.
- **Объём:** делай только текущий этап. Новые идеи записывай в «Идеи на потом» в `docs/PROGRESS.md`.
- **Правила игры:** не меняй и не додумывай. Неясность — в `QUESTIONS.md` и вопрос пользователю.
- **В конце этапа:**
  1. прогони проверки из раздела «Проверки» ТЗ;
  2. обнови `docs/PROGRESS.md`;
  3. закоммить;
  4. отчитайся коротко: что сделано, вывод проверок, что пользователю проверить руками, вопросы.
- **Если контекст заканчивается:** закоммить рабочее состояние, запиши в PROGRESS.md, что осталось, и предложи пользователю продолжить в новой сессии.
- **Перед необратимыми действиями** (force push, удаление веток или данных) — спроси пользователя.
- **Временные файлы и скрипты** удаляй в конце.

## Решения проекта

- Движок `src/engine/` — чистые функции без React и Node API: тот же код работает в браузере, на сервере и в симуляциях.
- Скрытая информация режется в `viewFor` на сервере, а не прячется в интерфейсе.
- Случайность — только seeded RNG из `src/engine/rng.ts`.
- Числа и тексты карт — только в `data/game-data.json`, не в коде.
- Пользователь проверяет работу на сайте GitHub Pages, своего компьютера с проектом у него может не быть.

## Язык

- Общение с пользователем и интерфейс — на русском.
- Код, имена и коммиты — на английском.

## Тесты

- Тест проверяет правило из ТЗ или `RULES.md`.
- Если тест кажется неверным, скажи об этом пользователю — не подгоняй тест под код.

## Команды

- `npm ci` — установка зависимостей (Node.js 22).
- `npm run dev` — сайт локально с автообновлением.
- `npm test` — тесты Vitest (`tests/**/*.test.ts`).
- `npm run typecheck` — проверка типов TypeScript.
- `npm run build` — сборка сайта в `dist/` (база `/bortom-k-bortu/` для GitHub Pages).
- `npm run convert-data` — пересобрать `data/game-data.json` из `reference/data3.py` (нужен Python 3). Затирает ручные правки JSON.
- `npm run sim` — консольный симулятор (появится на этапе 6).
- `npm run lan` — сервер для игры в локальной сети (появится на этапе 8).
- Публикация: `.github/workflows/pages.yml` — на каждый PR проверки (typecheck, test, build), после слияния в `main` ещё и выкладка на GitHub Pages.
