# Как сделать приложение через Claude Code в браузере

Ничего не нужно устанавливать: Claude Code работает на сайте claude.ai/code, код хранится на GitHub, а игра открывается по ссылке как обычный сайт. Нужна подписка Claude Pro или Max — Claude Code в браузере расходует её лимиты.

## Подготовка (один раз, около 15 минут)

1. **GitHub.** Зарегистрируйтесь на https://github.com/signup (бесплатно).
2. **Репозиторий.**
   - Откройте https://github.com/new.
   - Repository name: `bortom-k-bortu`.
   - Выберите **Public**: бесплатная публикация сайта работает только для открытых проектов.
   - Поставьте галочку **Add a README file**.
   - Нажмите **Create repository**.
3. **Файлы.**
   - Распакуйте архив.
   - В репозитории нажмите **Add file → Upload files**.
   - Перетащите в окно браузера всё содержимое папки `bortom-k-bortu-app`: `CLAUDE.md`, `START.md`, папки `docs` и `reference`.
   - Внизу нажмите **Commit changes**.
4. **Публикация сайта.** В репозитории: **Settings → Pages → Source → GitHub Actions**.
5. **Claude Code.**
   - Откройте https://claude.ai/code и нажмите **Sign in with GitHub**.
   - Под полем ввода выберите репозиторий `bortom-k-bortu`.

## Как проходит каждый этап

1. Нажмите **New session** и выберите репозиторий `bortom-k-bortu`.
2. Выберите режим. Обычно это **Accept edits**: Claude сам вносит правки. Перед этапами 3, 5, 7 и 8 выбирайте **Plan**: Claude сначала покажет план и ничего не будет менять, пока вы его не одобрите.
3. Отправьте `/model sonnet`, потом промпт этапа (ниже).
4. Отвечайте на вопросы, если они появятся. В конце Claude пришлёт отчёт с результатами проверок.
5. Нажмите **Create PR**, затем на GitHub **Merge pull request → Confirm merge**.
6. Через 1–2 минуты сайт обновится: `https://ВАШ-ЛОГИН.github.io/bortom-k-bortu/`. Зелёная галочка на вкладке **Actions** означает, что обновление готово.

Следующий этап — только в новой сессии и только после слияния. Длинная сессия дорожает с каждым сообщением и хуже держит инструкции, а всё нужное для продолжения лежит в `CLAUDE.md` и `docs/PROGRESS.md`.

## Промпты этапов

**Этап 1 — разбор правил** (режим Accept edits, модель лучше `/model opus`)

```
Этап 1 из docs/TZ.md. Прочитай PDF, data3.py и sim.py в reference/ и составь
RULES.md — свод правил по пунктам. Всё неясное и противоречивое собери в
QUESTIONS.md, затем задай мне эти вопросы по 3–4 за раз с готовыми вариантами
ответа. Мои ответы внеси в RULES.md. Код не пиши.
```

**Этап 2 — каркас и публикация**

```
Этап 2 из docs/TZ.md. Готово, когда: сайт публикуется на GitHub Pages через
GitHub Actions и показывает все 117 карт из data/game-data.json, а тесты
загрузчика данных проходят. Заполни раздел «Команды» в CLAUDE.md.
```

После слияния откройте сайт: на нём должны быть все карты. Если на вкладке Actions красный крестик, откройте его, скопируйте текст ошибки и отправьте в новой сессии: «Публикация падает с ошибкой: [текст]. Найди причину и исправь».

**Этап 3 — движок, часть 1** (режим Plan)

```
Этап 3 из docs/TZ.md. Сначала план: какие файлы и функции появятся и какие
тесты их проверят. После моего одобрения реализуй и покажи вывод npm test.
```

**Этап 4 — движок, часть 2**

```
Этап 4 из docs/TZ.md: Реакции (оба окна), особенности кораблей, Легенды, море.
Каждый пункт из «Правил-ловушек», который относится к ним, — отдельный тест.
Покажи вывод npm test.
```

**Этап 5 — все карты** (режим Plan)

```
Этап 5 из docs/TZ.md. Заведи в docs/PROGRESS.md список всех карт со статусом
и делай их по одной колоде: реализация, тест, отметка в списке, коммит.
Карты, которые sim.py упрощает, делай точно по тексту (раздел ТЗ об упрощениях).
```

Если сессия остановится на середине, нажмите Create PR → Merge, откройте новую сессию и напишите: «Продолжи этап 5 по списку карт в docs/PROGRESS.md».

**Этап 6 — боты и проверка баланса**

```
Этап 6 из docs/TZ.md. Перенеси ботов из reference/sim.py без улучшений и сделай
npm run sim. Покажи таблицу: наши 3000 партий против PDF, страница 26
(победы сторон, раунды, Порох по статьям). Расхождение больше 3 процентных
пунктов — найди и объясни причину.
```

**Этап 7 — игра на одном экране** (режим Plan)

```
Этап 7 из docs/TZ.md. Готово, когда: на опубликованном сайте можно доиграть
партию до конца вдвоём за одним ноутбуком и против ботов. Стол помещается
на экране ноутбука, на телефоне — компактный вид.
```

После слияния сыграйте партию. О каждой ошибке пишите в новой сессии по шаблону ниже.

**Этап 8 — игра по сети** (режим Plan)

```
Этап 8 из docs/TZ.md: игровой сервер с режимами npm run lan и Docker + Caddy,
комнаты, одновременные ходы, окно Реакций с таймером, переподключение.
Готово, когда: интеграционный тест сервера с 2–4 клиентами проходит, и написан
DEPLOY.md для новичка.
```

После слияния откройте в репозитории `DEPLOY.md` и выберите способ. Для игры в одной Wi-Fi сети нужен один ноутбук с установленным Node.js, сервер не нужен. Для игры через интернет — арендованный VPS, около 30 минут настройки по инструкции.

**Этап 9 — лаборатория баланса и редактор**

```
Этап 9 из docs/TZ.md. Добавь пресет «Пушки: эксперимент» с разными параметрами
Залпа у кораблей. Готово, когда: на сайте можно сравнить v0.3 и этот пресет
на 1000 партий ботов.
```

**Этап 10 — полировка и проверка**

```
Этап 10 из docs/TZ.md. Сначала используй субагента, чтобы он проверил проект
по docs/TZ.md: каждое требование реализовано, у правил есть тесты, ничего лишнего
не добавлено. Пусть сообщает только пробелы, влияющие на правила или требования.
Исправь найденное, затем экспорт и импорт и README.
```

## Шаблон сообщения об ошибке

```
Ошибка. Что сделал: [...]. Что ожидал: [...]. Что увидел: [...].
Сначала напиши тест, который воспроизводит ошибку, потом исправь
и покажи, что тест проходит.
```

Скриншот можно просто вставить в сообщение.

## Как не сжечь лимиты

- **Один этап — одна сессия.** Слияние после каждого этапа обязательно.
- **Модель.** По умолчанию `/model sonnet`. Opus — для этапа 1 и для случаев, когда Sonnet не справился.
- **Дважды поправили, а Claude всё ещё ошибается** — не продолжайте спорить. Откройте новую сессию и напишите промпт заново, сразу учтя, что пошло не так. По опыту Anthropic, чистая сессия с лучшим промптом почти всегда работает лучше длинной с поправками.
- **Просите конкретное.** «Исправь X в Y, проверь тестом» вместо «сделай лучше».
