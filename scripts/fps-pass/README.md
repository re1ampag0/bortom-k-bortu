# fps-pass: диагностика воспроизводимости

**Эталон принят пользователем.** Текущий порог: RGB >48, доля ≤0,05%, 8-связная область ≤16 px либо не хуже A/A этого момента. Актуальный результат: `docs/progress/fps-pass.md`.

База приложения: main `5f097c58`, PR85. Скрипты работают отдельно от игры и не попадают в сборку.

## Повторить

Node.js22+, зависимости проекта, Chromium (в текущей среде `/usr/bin/chromium`, иначе браузер Playwright; путь можно задать через CHROMIUM_PATH). Из корня репозитория в первом терминале:

```
node scripts/fps-pass/server.mjs
```

Во втором терминале (подходит и для PowerShell):

```
node scripts/fps-pass/calibrate.mjs
node scripts/fps-pass/matrix.mjs --scenes=armada --sizes=390x844 --name=repeat-check
```

Матрица сначала записывает reference, затем сравнивает с повторным запуском того же приложения. Копия `clock.mjs`, `record.mjs`, `movie.mjs` фиксируется на время пары во временном каталоге ОС `fps-protocol-<hash>`; хеш входит в имена файлов и JSON. Разработка следующего адаптера не меняет уже запущенную пару. По умолчанию перечислены все запрошенные сцены, покой/цель и окна; это возможности скрипта, **не заявление об их успешной проверке**.

В логе матрицы будет тег `baseline-<hash>-compare-armada-390x844`. Карты различий строятся так (подставить выведенный тег):

```
node scripts/fps-pass/compare.mjs baseline-6c05a5ddfc5a2917-compare-armada-390x844
```

A/A принят: протокол 08d497086514406a, 56 сравнений. Итоговая неизменность приложения не подтверждена; работа остановлена на существующем падении e2e, воспроизведённом на main. Код выхода матрицы2 означает необходимость разбора различий,1 означает ошибку записи;0 не доказывает автоматически весь контракт А–В.

## Часы и рисунок

- `page.clock.install/pauseAt/runFor`; кадры через50мс игрового времени.
- CDP `Animation.setPlaybackRate=0.1` при продвижении времени,0 при чтении состояния/PNG. JS в этот момент не продвигается.
- Отдельные часы CSS/WAAPI/SMIL согласуются с виртуальными; остановка/продолжение и finished проверяются calibrate.mjs. Нативные завершения получают логические Promise, чтобы физическое время не определяло уборку объектов.
- rAF и idle callback в адаптере привязаны к виртуальной сетке; функции игры и исходные keyframes не редактируются. Фоновая CSS-фаза начинается от общего начального epoch. MutationObserver/ResizeObserver/IntersectionObserver полностью не виртуализированы, это остаётся ограничением метода.
- Начальная раскладка получает два физических кадра при остановленном игровом времени.
- Последний протокол: последовательный запуск без конкурентных захватов, Chromium `--disable-gpu --disable-threaded-animation`; перед записью требуется два одинаковых RGBA-снимка одного остановленного момента, максимум8 попыток.
- Полные PNG, DPR1, без масштабирования, масок и исключений областей. Нативные замеры DPR3/CPU×4 записаны отдельно, см. `m*-native.json`; эти цифры не получены виртуальными часами. Адаптер часов нельзя использовать для измерения настоящего FPS.
- Сохраняются и общее число отличающихся пикселей, и число значимых по принятому порогу. Текущий порог: значимость >48, доля ≤0,05%, область ≤16 px либо не хуже A/A того же момента. 8-связные области считаются в pixels.mjs. Непрошедший кадр требует разбора и не получает автоматического исключения.

## Формат и артефакты

movie.mjs пишет FPA1: ширина/высота RGBA, затем время, размер и XOR с предыдущим кадром в deflate. Декодирование без потерь через reader.frame(); проверен roundtrip. Полные локальные архивы в `docs/measurements/fps-pass/frames/`, они исключены из Git из-за объёма и воспроизводятся командой выше. Худшие полные кадры, карты отличий, JSON, использованный протокол и вывод проверок включены в Git.

`record.mjs` собирает промежуточные наблюдения DOM/canvas и elementFromPoint. Они ещё не являются полным доказательством первого видимого пикселя каждого экземпляра, его привязки к событию и всех отношений слоёв. Контракт Б/В не объявлен выполненным.

Зафиксированный протокол первоначальной диагностической пары находится в `docs/measurements/fps-pass/protocols/6c05a5ddfc5a2917/`. Текущие launcher-скрипты также поддерживают выбор браузера на Windows; это меняет хеш протокола, но в текущей Linux-среде выбирает тот же executablePath. Исходные три файла диагностической пары сохранены без изменений.


## Новый порог и повторы

`pixels.mjs` считает >48 по RGB (alpha не сравнивается, скриншот непрозрачен), долю и крупнейшую 8-связную область. `record.mjs` сохраняет числа каждого кадра; `NOISE_FILE` задаёт JSON повторного A/A и применяется только для того же момента. Архивы остаются lossless. `matrix.mjs --after=1 --name=m1` сравнивает с подготовленными архивами и A/A. `--resume=1` пропускает завершённые записи, `--jobs=2` допускает независимые визуальные записи параллельно. Нативные замеры всегда отдельно, без других захватов: `PORT=5432 node scripts/fps-pass/measure.mjs before sea-fleet idle`, потом PORT=5431/after. В PowerShell задайте `$env:PORT='5432'` отдельной командой.

В новом адаптере та же сетка завершения 10 мс работает внутри страницы; один CDP-вызов продвигает весь интервал 50 мс. Калибровка delay/finished/pause/resume повторно прошла. Имена протокола включают clock/record/movie/pixels, метрики с настоящими часами от них независимы.

## Состояние передачи

Полная актуальная сводка: `docs/measurements/fps-pass/handoff-validation.json`. Приложение итогового частичного прогона: неизменяемый `406dc6f3`, протокол `d0eade412462bacd`. `final-compare-*` являются черновиками с риском HMR, не доказательством. `verified-compare-*` содержат 18 завершённых случаев и четыре случая с нерешёнными отличиями; матрица не завершена.

Для экономии места полные JSON-наблюдения сжаты без потерь в соседний `.full.json.gz`. Обзорный JSON сохраняет метрики кадров и поле `fullRecord`; `readRecords` из `record-data.mjs` автоматически читает оригинал. `pack.mjs` запускать только после завершения записей. Архивы кадров FPA1 не включены в Git; они воспроизводятся записью. Наличие PNG/нулевых частичных сравнений само по себе не доказывает контракт А–В.
