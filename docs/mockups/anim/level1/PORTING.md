# Как перенести эталон анимаций в игру

Этот файл — для Claude Code. Читай его целиком перед любой задачей A1–A4, S1, L1.
Эталон — рабочий код, проверенный на событиях настоящего движка. **Переноси код, а не придумывай заново.**
Если в игре что-то устроено иначе, чем здесь написано, — остановись и спроси пользователя.

## 1. Что такое эталон

`anim-demo.html` — стол игры с 62 сценами. Каждая сцена — **настоящие события движка** из партий ботов
(как их видит один игрок после `eventsFor`), а не выдуманные. Открой страницу в браузере (двойной щелчок
по файлу): слева стол, справа «События движка» и «Клипы (planfx)» с проверкой ✓ у каждого выстрела.

Файлы (каждый — обычный `<script>`, без сборки; порядок подключения важен):

| Файл | Что внутри | Куда в игре |
|---|---|---|
| `planfx.js` | чистые функции: `createPlanner` (события → клипы), `layoutShots` (ядра), `applyVisible` (отображаемое состояние) | `src/ui/game/fx/planFx.ts`, `src/ui/game/fx/display.ts` |
| `effects.js` | примитивы: `fly`, `flash`, `burst`, `splash`, `tag`, `pillAt`, `payKegs`, `gainKegs`, `flyCard`, `setTrack`, `fxPoint`, DOM-контракт | `src/ui/game/fx/primitives.ts` |
| `play-volley.js` | клипы Залпа: `announce`, `window`, `reaction`, `shot`, `cancel`, `counter`, `heart` | `src/ui/game/fx/volley.ts` |
| `play-misc.js` | смена мест, погружение, гибель, ход, карта, ремонт, Порох, Души, статусы, добор, кости, итог; макеты P2/P3 | `src/ui/game/fx/misc.ts` |
| `play-sea.js` | карты моря (клип `sea`) и тихий фон раунда `renderWeather` | `src/ui/game/fx/sea.ts` |
| `play-legends.js` | Легенды: общий выход + «Армада», «Кракен», «Корабль в бутылке», «Джек ускользает» | `src/ui/game/fx/legends.ts` |
| `style.css` | раздел «ЭФФЕКТЫ» (от `.fx-layer` до конца, кроме «СТРАНИЦА») | `src/ui/game/fx/fx.css` |
| `board.js`, `page.js` | стол и страница эталона — **не переносить**; из `page.js` переносится только идея очереди (раздел 4) | — |
| `data.js`, `scenes.js` | данные игры и сцены (сгенерированы `build-data.py`, `build-scenes.py`) — **не читать целиком**, это данные | — |

Не читай `data.js` и `scenes.js` инструментом Read — это две огромные строки. Нужны события сцены —
смотри панель «События движка» на странице или запусти `node -e` с `require`.

## 2. Главная идея (запомни)

1. Движок отдаёт события действия. **Планировщик** (`createPlanner().feed(events, action)`) превращает их
   в клипы. Каждый клип помнит индексы своих событий (`clip.ev`). Каждое событие попадает ровно в один
   клип или в `quiet` — это проверяет `validate.cjs`.
2. **Отображаемое состояние** `D` отстаёт от настоящего: планшеты рисуются из `D`. Клип играет →
   к `D` применяются события клипа (`applyVisible`) → перерисовка. Когда очередь пуста, `D` = настоящее
   (проверено на 400 партиях). Кнопки и проверки «можно ли» — всегда по НАСТОЯЩЕМУ состоянию.
3. **Ядро = 1 урон.** `layoutShots` раскладывает ядра так, что долетевших (`hit` + `overkill` + `moon`)
   ровно `damage`, по шкале — `amount`, в Корпус — `toHull`. Минусы разбора — ядра, которые не долетели.
4. Слой эффектов — `pointer-events: none`. Анимация никогда не блокирует нажатия. Нажатие по столу
   во время показа — сразу итог. Карты в руке и журнале открываются всегда.
5. Двигаем только `transform` и `opacity` (WAAPI `element.animate`). Длительности × множитель скорости.

## 3. DOM-контракт: атрибуты, по которым эффекты находят стол

Эффекты не знают про React. Они ищут элементы по атрибутам `data-fx-*`. Добавь их в разметку игры:

| Атрибут | Элемент в игре | Файл |
|---|---|---|
| `data-fx-ship="<код>"` | `<section class="plank …">` планшета корабля | `Table.tsx`, `Plank` |
| `data-fx-track="hull\|sails\|guns\|crew"` | строка шкалы `.track.t-*` | `Table.tsx`, `Plank` |
| `data-fx-value` | число шкалы `.track-num` | `Table.tsx` |
| `data-fx-fires`, `data-fx-souls`, `data-fx-legend` | значки `.badge.fire`, `.badge.souls`, `.badge.legend` | `Table.tsx` |
| `data-fx-statuses` | `.plank-statuses` | `Table.tsx` |
| `data-fx-hold="<сторона>"` | `.powder-dots` команды; каждый бочонок `<i data-fx-keg>` | `Table.tsx`, `PowderDots`, `TeamRow` |
| `data-fx-gap` | средняя полоса `.middle` между рядами | `Game.tsx` |
| `data-fx-hand` | `.hand-row`; карты в руке `data-fx-card="<код>"` | `Game.tsx`, `Hand.tsx` |
| `data-fx-deck` | `.deck-info` | `Hand.tsx` |
| `data-fx-instruction` | `.status-text` строки состояния | `Table.tsx`, `StatusBar` |
| `data-fx-sea-chip` | кнопка `.chip.sea` | `Table.tsx`, `StatusBar` |

Слой эффектов: `<div class="fx-weather">` и `<div class="fx-layer" aria-hidden="true">` — последние дети
доски (`.board`, `position: relative`). Ширина планшетов на телефоне другая: там у Корпуса полоска, у
остальных шкал окошко с числом — `fxPoint` уже это учитывает (клетка → полоска → число).

## 4. Очередь показа (из `page.js`, функция `play`)

```
D = отображаемое состояние (копия настоящего на момент, когда очередь была пуста)
на каждое действие (события после eventsFor):
  clips = planner.feed(events, action)
  для каждого клипа:
    clip.events = clip.ev.map(i => events[i])
    await PLAY[clip.kind](clip, run)          // может быть прерван: run !== RUN → исключение ABORT
    применить к D события клипа по порядку индексов (applyVisible) → перерисовать
    строка журнала клипа
  применить к D события из clips.quiet
скорость «мгновенно», prefers-reduced-motion, «Сразу итог», нажатие по столу → D = настоящее, слой очищен
```

В React: `useFxQueue` хранит `D` в `useRef` + счётчик для перерисовки; `Table` получает `display`
(поля `tracks, pos, fires, sunk, submerged, souls, legend, powder, sea, round, active` из `D`, остальное —
из настоящего состояния). Между клипами одного Залпа сцена Залпа (`VS`: плашка, карты у плашки,
наклоны планшетов) **переживает перерисовку** — в эталоне это делает `afterRender()`; в React — потому что
узлы не пересоздаются, но проверь, что `key` планшетов стабилен.

Устойчивые состояния (наклон «Уйти по ветру», вода «Под водой», подсветка стреляющего) — inline-стиль или
CSS-класс из состояния, а не анимация с `fill: 'forwards'` (её сотрёт перерисовка).

## 5. Ловушки настоящих событий (всё это уже учтено в `planfx.js` — не «упрощай»)

- Объявление (`volley` + `windowOpened`) и выстрел (`reaction`/`noReaction` + `hit` + `damage`) часто
  приходят **разными действиями**. Планировщик помнит незаконченный Залп (`state.vol`).
- `hit.terms` — разбор ПОСЛЕ Реакций. У `volley` разбора нет (A1 добавляет `volley.terms`).
  У `Term` нет `src` (A1 добавляет); пока источник угадывается по тексту `what` (`termSrc`).
- Урон бывает меньше суммы слагаемых без строки разбора («Зомби-офицеры», «Морская пехота» —
  `cancel_crew`): лишние ядра летят «в заслон».
- `damage.toHull` — перелив в Корпус; лишний урон по пустой шкале — `overkill`; «Лунный свет» −1 по
  Команде — `moon`.
- «Залп с обоих бортов» — два `volley` подряд с тем же Зарядом (`fx.both`): второй — `part: 2`.
- Ответ Реакции (`fx.counter`) — урон стрелявшему ПОСЛЕ `hit` → клип `counter`.
- «Корабль в бутылке» топит событием `sunk` без `damage` (`applyVisible` ставит Корпус 0).
- «Джек ускользает»: `jackEscaped` + `swapped` с одним кораблём (союзник затонул). Затонувший стоит
  на свободном месте (как `Game.tsx`, строки 428–429).
- Порядок начала хода — по событиям (доход → Пожар → эффекты моря → всплытие → Мальстрём → добор).
- «Девятый вал» сейчас не шлёт `seaEffect` — урон по Парусам приходит в клипе `turn` (A1 добавляет
  `seaEffect { key: 'wave' }`, планировщик уже готов).
- Цена: `powderSpent`/`soulsSpent` приходят ДО действия; планировщик забирает их по `reason`.

## 6. Проверки, которые ты обязан запустить

```
npx vite-node scripts/dump-fx-events.ts -- --games 100 --seed 1001 --out tmp/fx-games.json
npx vite-node scripts/dump-fx-events.ts -- --games 50 --seed 2001 --out tmp/fx-net.json --net
node docs/mockups/anim/level1/validate.cjs tmp/fx-games.json data/game-data.json      → «ВСЁ СОВПАЛО»
node docs/mockups/anim/level1/validate.cjs tmp/fx-net.json data/game-data.json        → «ВСЁ СОВПАЛО»
```

После переноса в TypeScript тот же прогон делает тест `tests/fx-plan.test.ts` (A1) уже над твоим
`planFx.ts` — без JSON, партии ботов прямо в тесте. Эталон и порт должны давать **одинаковые клипы**
на одинаковых событиях (тест сравнивает `kind` и раскладку ядер).

Кадры для сравнения: `node docs/mockups/anim/level1/capture.mjs <сцена> <мс,…> 1366x660 <папка>`
(`capture.mjs list` — список сцен). Снимай те же моменты в игре (e2e) и клади рядом.

## 7. Чего не делать

- Не выбирать анимацию по названию карты — только по событиям и `fx` карты (исключение — три вида
  отмены Залпа в `PLAY.reaction`, там название только меняет картинку; вынеси в `fx.look` при переносе,
  если пользователь согласится).
- Не трогать правила, ботов, баланс (`npm run sim -- --games 3000 --seed 1` → Пираты 46,5 %).
- Не рисовать кадры из фильмов и узнаваемые образы — только свои SVG/CSS из эталона.
- Не блокировать ввод: ни один элемент слоя эффектов не ловит нажатия.
