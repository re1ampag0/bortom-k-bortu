# ТЗ: цифровой прототип настольной игры «Бортом к борту»

## Цель

Браузерное приложение для студенческой команды, которая разрабатывает настольную игру. Оно нужно, чтобы:

1. **Играть по правилам без бумаги:** за одним устройством или каждый со своего — в одной Wi-Fi сети или через интернет. На любое место можно посадить бота.
2. **Менять правила и числа без правки кода:** характеристики кораблей, Порох, стоимость и сила карт.
3. **Проверять баланс:** прогнать тысячи партий ботов и сравнить два варианта правил.

Важнее всего точные правила, быстрая смена чисел и честная статистика. Красота вторична: это инструмент для тестов.

## Вне рамок

Это не делаем, даже если кажется полезным. Идеи записывай в раздел «Идеи на потом» в `docs/PROGRESS.md`.

- Арт, анимации, звук. Карты и планшеты рисуются на CSS.
- Аккаунты, регистрация, рейтинги, чат (игроки разговаривают голосом).
- Соединение напрямую между браузерами (WebRTC, PeerJS). Сеть только через наш сервер.
- Боты умнее, чем в `reference/sim.py`.
- Приложения для магазинов, PWA, офлайн-кэш.

## Архитектура

- **Стек:** TypeScript, React, Vite, Vitest; сервер — Node.js 22 и библиотека `ws`. Один репозиторий, один `package.json`.
- **Один движок на всё.** `src/engine/` — чистые функции без React и без Node API:
  `applyAction(state, action, data, rng) → { state, events }`.
  Состояние — обычный JSON-объект. Этот же движок работает в браузере, на сервере и в симуляциях, поэтому правила существуют в одном экземпляре.
- **Видимость.** Функция `viewFor(state, playerId)` возвращает состояние без чужих скрытых карт. Её используют и интерфейс на одном экране, и сервер.
- **Случайность** только через seeded RNG (например, mulberry32): партия однозначно воспроизводится по `seed` и списку действий.
- **Транспорт.** Интерфейс общается с движком через `Transport`. Для игры на одном устройстве — локальный транспорт (движок в браузере), для сети — WebSocket к серверу.
- **Симуляции** в браузере — в Web Worker, чтобы интерфейс не зависал. В консоли — `npm run sim`.
- **Сайт** — статический, публикуется на GitHub Pages через GitHub Actions после каждого слияния в `main`. Пользователь работает в Claude Code в браузере и проверяет результат только на опубликованном сайте.

```
data/game-data.json        — все данные игры
data/presets/              — сохранённые варианты правил
scripts/convert-data.*     — data3.py → game-data.json
src/engine/                — движок: types, data, rng, setup, turn, volley, reactions, effects,
                             abilities, legends, sea, view, ai/, sim/
src/ui/                    — интерфейс
src/net/                   — Transport: local и websocket
server/                    — игровой сервер
tests/
docs/                      — ТЗ и PROGRESS.md
```

## Данные

- Перенеси всё из `data3.py` в `data/game-data.json` **скриптом**: ручной перенос 117 карт даст ошибки. Сохрани все поля: `name, type, cost, soul, big, text, flavor, v, fx, legend, tags`, число копий, корабли с особенностями и подсказками, Легенды, море (с полем `key`), `ECON`.
- Названия операций в `fx` оставь как в `data3.py` (`draw`, `dmg`, `fire`, `reduce`, `cancel`, `counter` и т. д.), чтобы данные можно было переносить обратно без потерь.
- При загрузке проверяй данные. Неизвестная операция, отрицательная стоимость, пустое название — понятная ошибка с названием карты.
- **Параметры Залпа у корабля** — задел на эксперименты с пушками. По умолчанию как в версии 0.3, и пока они по умолчанию, интерфейс не меняется:
  - `volleyCost` — Порох за Залп (1);
  - `diagDamage` — урон по диагонали: смещение (−1) или своё число;
  - `defaultTrack` — шкала, по которой Залп бьёт без Заряда (`hull`);
  - `volleysPerTurn` — Залпов за ход (1);
  - `volleyModes` — необязательные фирменные режимы Залпа на планшете. Каждый описан как Заряд (`fx` и доплата Порохом) и доступен каждый ход, не занимая карту.

## Правила, которые легко сделать неправильно

Каждый пункт сверь с PDF и покрой тестом.

- **Раунд:** открыть карту моря → ход Пиратов → ход Компании. Карта «Сразу» срабатывает один раз при открытии, «Весь раунд» действует до следующей карты моря.
- **Трюм:**
  - в начале своего хода команда получает +3 Пороха, в самый первый ход Пираты — +2;
  - больше 8 Пороха не бывает, излишек сгорает;
  - Компания начинает игру с 4 Порохами (в варианте «Первая партия» — с 3);
  - сразу после Трюма Пожары наносят по 1 урону Корпусу за каждый Пожар, раньше любых действий.
- **Добор:** до 5 карт. Планы «Жемчужины» считаются картами в руке.
- **Лимиты:**
  - за свой ход корабль разыгрывает не больше карт, чем его Команда; Заряд тоже считается;
  - за ход противника корабль играет не больше Реакций, чем его Паруса;
  - Реакции из Планов «Жемчужины» и Легенда «Джек ускользает» идут сверх этого лимита.
- **Свободные действия** (не считаются розыгрышем):
  - продать карту за +1 Порох — раз в ход на игрока;
  - передать 1 карту союзнику — раз в ход на игрока;
  - Перестроение — раз в ход на команду за 1 Порох; пока «Жемчужина» на плаву, у Пиратов бесплатно; нельзя, если у любого из двух кораблей Паруса 0;
  - потушить Пожар: сбросить карту и снять 1 Пожар, без ограничений.
- **Залп:**
  - стоит 1 Порох, цель — корабль напротив или по диагонали, не больше 1 Заряда;
  - урон = Пушки, по диагонали −1, без Заряда бьёт по Корпусу, урон не меньше 0;
  - совместный залп: +1, если второй корабль команды в этот ход стреляет по той же цели, что и первый; бонус даётся один раз за ход, даже если был третий Залп по Сердцу Джонса.
- **Реакции** играют после объявления Залпа (цели и Заряда) или карты против команды, до урона. Карты со словами «после Залпа» — после урона. Значит, окон Реакций два: «до урона» и «после Залпа».
- **Урон:**
  - урон по шкале на минимуме (Паруса 0, Пушки 0, Команда 1) переносится остатком в Корпус;
  - Корпус 0 — корабль тонет;
  - Ремонт не поднимает шкалу выше стартового значения.
- **«Это не Залп»:** на такие карты не действуют диагональ, совместный залп и Реакции на Залп. Реакции «на Залп или карту» действуют.
- **Корабль тонет:** его особенности и неразыгранная Легенда уходят из игры. Капитан переходит на борт союзника:
  - в свой ход разыгрывает 1 карту за союзника сверх его лимита;
  - может добавить свой Заряд в Залп союзника, если тот не сыграл свой;
  - в ход противника играет 1 Реакцию сверх Парусов союзника.

  Одинокий корабль может Перестроением (1 Порох) перейти на пустое место.
- **Особенности кораблей** — ровно по тексту планшетов: Безумный план, Быстрее ветра, Греческий огонь, Меч Тритона, Казна Компании, Сердце Дейви Джонса, Вечная служба, Погружение.
  - **Погружение:** вместо Залпа; гасит Пожары; до своего следующего хода корабль нельзя выбрать целью, и он не играет Реакции; после всплытия первый Залп +1 и без Реакций.
  - **Души:** «Голландец» начинает с 1 Душой, максимум 5.
- **Легенды** лежат открыто и играются один раз за свою стоимость: Джек — 2 Пороха, Бутылка — 3 Пороха, Армада — 2 Пороха, Кракен — 3 Души.
- **Конец игры:** у команды потоплены оба корабля. Если последние корабли обеих команд утонули одновременно — ничья.

## Где `sim.py` упрощает, а приложение должно делать точно

В `sim.py` часть карт упрощена ради скорости. В приложении делай по тексту карт:

- **«Ловкость рук»:** сыгранная противником карта уходит в руку игрока «Жемчужины».
- **«Компас Джека»:** посмотреть 3 верхние карты, одну взять в руку, одну положить в План, одну сбросить.
- **«Безумный план»:** выбранная карта уходит в План.
- **«Анжелика»:** союзнику передаётся выбранная карта.
- **«Тиа Дальма»:** посмотреть 3 верхние карты моря и переложить их в любом порядке.
- **«Игра в кости лжеца»:** оба игрока выбирают карту втайне друг от друга.
- **«Тортуга»:** команды сами решают, сколько Пороха тратить и кому достаются карты.
- **Бонусы «План:»** у всех карт, включая «Латаем паруса» (+1 Корпус).
- **«Блокада»:** запрещает и Ремонт, и смену мест.
- **«Удачный манёвр»:** в версии 0.3 убран из колод, не добавляй.

Все решения игрока — выбор цели, карты, шкалы для Ремонта — делаются через интерфейс. Боты принимают те же решения своей логикой.

## Интерфейс

- **Экран настройки:**
  - режим: один экран или по сети;
  - кто за какой корабль (человек или бот);
  - варианты: море, Легенды, «Первая партия», «Быстрый бой»;
  - seed и набор данных (пресет).
- **Стол:**
  - 4 планшета 2×2: Компания сверху, Пираты снизу. На каждом шкалы, Пожары, Души, «Под водой», Легенда;
  - Трюмы обеих команд с числом Пороха;
  - карта моря, номер раунда, чья очередь.
- **Рука:**
  - своя рука — крупно внизу, рука союзника — рядом помельче, Планы «Жемчужины» — отдельной полоской;
  - у вражеских кораблей видны только рубашки и число карт;
  - карта, которую сейчас нельзя сыграть, серая, а подсказка при наведении объясняет почему: нет Пороха, исчерпан лимит Команды, не та фаза.
- **Залп:** кнопка у корабля → выбор цели с подсветкой (напротив или по диагонали) → выбор Заряда из руки → **предпросмотр урона с разбором**, например «3 (Пушки) +1 (Ядра) −1 (диагональ) +1 (совместный) = 4 по Корпусу» → подтверждение.
- **Реакции.** Когда противник объявил Залп или карту, защищающейся команде показывается окно со списком доступных Реакций и тем, каким станет урон. Если доступных Реакций нет, окно не показывается.
- **Журнал** сбоку: каждое действие словами с расчётом, например «Месть: Залп по Голландцу. 3 (Пушки) +1 (Ядра) −1 (Водоворот) = 3 по Корпусу. Корпус 5 → 2».
- **Партии:**
  - экспорт журнала в .txt и партии в .json (seed и действия); загрузка .json воспроизводит партию;
  - автосохранение текущей партии в localStorage;
  - Undo — только в игре на одном экране.
- **Боты:** ход показывается с паузой 0,5–1 с, есть кнопки «быстрее» и «до конца хода».
- **Экраны:** работает на ноутбуке и на телефоне. На узком экране планшеты компактные, а рука прокручивается горизонтально.
- **Язык:** интерфейс на русском, код, имена и коммиты — на английском.

## Мультиплеер

### Режимы

1. **Один экран.** Все за одним ноутбуком. Видны карты только той команды, которая сейчас ходит. Когда ход переходит или противнику пора решать про Реакцию, экран закрывается заставкой «Передайте устройство: ходит Компания». Карты появляются после нажатия «Показать».
2. **По сети через игровой сервер.**
   - Один игрок нажимает «Создать комнату» и получает код из 5 символов и ссылку. Остальные открывают ссылку или вводят код и выбирают свободный корабль.
   - На пустые места можно посадить ботов. Ботов считает сервер.
3. **Боты** — на любом месте в обоих режимах. Партия из 4 ботов — просмотр матча.

### Игровой сервер

Почему сервер, а не соединение напрямую между браузерами: через сервер играют и из университетской сети, партия не обрывается, если кто-то вышел, и всё можно проверить тестами в облачной сессии Claude Code.

- `server/` использует тот же `src/engine`, второй копии правил нет.
- После каждого действия партия сохраняется в файл `server-data/rooms/<код>.json`, поэтому после перезапуска сервера игры продолжаются. Комната удаляется после 24 часов без действий.
- Игрок получает токен своего места и хранит его в localStorage. После обновления страницы или обрыва связи он автоматически возвращается на место. Вышедшего игрока, включая создателя комнаты, можно заменить ботом.
- Сервер отправляет каждому игроку только `viewFor(state, playerId)`: чужие руки по сети не передаются вообще. Он проверяет, что действие пришло от игрока, которому оно разрешено, и ограничивает частоту сообщений.
- Эндпоинт `/health` отвечает, жив ли сервер.
- **Два способа запуска одного и того же кода:**
  - **Wi-Fi.** `npm run lan` на одном ноутбуке. Сервер раздаёт и сам сайт, и игру по адресу вида `http://192.168.1.23:8080` и печатает этот адрес в консоли. Остальные в той же сети открывают его в браузере.
  - **Интернет.** Арендованный VPS, `Dockerfile` и `docker-compose.yml` с Caddy, который сам получает HTTPS-сертификат. Сайт на GitHub Pages подключается к `wss://<домен>`; адрес сервера задаётся при сборке (`VITE_SERVER_URL`) и меняется в настройках клиента.
- **`DEPLOY.md` для новичка** — пошагово, с готовыми командами:
  - **Wi-Fi:** установить Node.js, скачать проект с GitHub (Code → Download ZIP), `npm install`, `npm run lan`, что открыть на других устройствах, что делать, если брандмауэр Windows спросит про доступ;
  - **VPS:** какой сервер заказать (Ubuntu 24.04, 1 ядро, 1–2 ГБ памяти), домен или бесплатный поддомен DuckDNS, вход по SSH, установка Docker одной командой, `git clone`, файл `.env`, `docker compose up -d`, проверка `https://<домен>/health`, обновление: `git pull && docker compose up -d --build`.

### Одновременные ходы

- Союзники действуют одновременно, каждый со своего устройства. Сервер применяет действия по порядку прихода. Порох проверяется в момент применения: если союзник его уже потратил, игрок видит отказ с объяснением.
- Ход команды заканчивается, когда «Ход окончен» нажали оба игрока команды. Бот нажимает сразу.
- **Окно Реакций** открывается одновременно у всех игроков защищающейся команды, каждый решает за свой корабль. Сервер ждёт ответа «Сыграть» или «Пропустить» от всех, но не дольше таймера. Таймер по умолчанию 30 с, настраивается в комнате; 0 — без таймера. Атакующие в это время видят «Противник думает над Реакцией…».
- **Тайный выбор** («Игра в кости лжеца»): оба выбирают у себя, сервер вскрывает одновременно.

### Кто что видит

| Информация | Своя команда | Противник |
|---|---|---|
| Шкалы кораблей, Пожары, Души, «Под водой» | видно | видно |
| Легенды (лежат открыто, пока не сыграны) | видно | видно |
| Порох в Трюме **обеих** команд | видно | видно |
| Карта моря, журнал, сброшенные карты | видно | видно |

| Колоды | только число карт | только число карт |

В настройках комнаты две галочки: «Союзники видят руки друг друга» (по умолчанию включено) и «Всё открыто» (для тестов, по умолчанию выключено).

## Боты

- Перенеси логику класса `AI` из `sim.py` без «улучшений»:
  - жадная оценка карт и целей;
  - резерв Пороха под Залпы и платные Реакции;
  - Меч Тритона, Погружение, Сердце Джонса, тушение Пожаров, продажа карт, Планы, Легенды.
- Цель — чтобы статистика совпадала с Python: тогда сравнения вариантов правил будут честными.

## Лаборатория баланса

- **Запуск:** два набора данных (A и B), число партий (100–5000), seed, варианты правил, кто ходит первым.
- **Результаты по каждому набору:**
  - победы сторон с 95% доверительным интервалом;
  - длина партии в раундах: среднее и 10–90%;
  - Порох за ход по статьям: доход, на Залпы, на карты, на Реакции, на особенности, сгорело; доля ходов, закончившихся с пустым Трюмом;
  - сколько раз за партию разыгрывается каждая карта в пересчёте на копию: самые частые и «мёртвые» карты;
  - урон по источникам;
  - использование Легенд и особенностей.
- A и B показываются рядом, значимые различия подсвечены.
- Переключатели «Отключить особенность» (как `cfg.off` в `sim.py`) — для быстрых экспериментов.

## Редактор данных

- **Таблицы:**
  - корабли, включая параметры Залпа;
  - экономика;
  - карты: стоимость, число копий, числа внутри `fx`, ценность `v`;
  - море: включение и выключение отдельных карт.
- Сохранение пресетов, экспорт и импорт JSON.
- Если поменяли `fx`, а текст карты нет, показывается предупреждение «текст карты мог устареть».
- Колонки «ценность / норма / перевес» по формуле из PDF, страница 25: норма Заряда 1, Реакции 1,5, Приказа и Ремонта 2; +1 за каждый Порох или Душу; +2 у Легенды.

## Проверки

Работа считается сделанной, только когда проверки проходят и их вывод показан в отчёте.

- `npm test`, `npm run build`, `npm run typecheck` — без ошибок.
- Тест на каждый пункт раздела «Правила, которые легко сделать неправильно».
- Хотя бы один тест на каждую карту: состояние до → розыгрыш → состояние после.
- `viewFor`: противник никогда не получает чужую руку, Планы и порядок колод.
- **Инварианты на 1000 партий ботов:**
  - Порох от 0 до 8, все шкалы в допустимых пределах;
  - партия заканчивается не позже 30 раундов;
  - нет исключений;
  - одинаковый seed даёт одинаковый результат.
- **Эталон баланса.** `npm run sim -- --games 3000 --seed 1` на данных v0.3 даёт результат, близкий к PDF (страница 26): Пираты около 47%, около 4,6 раунда, Порох по статьям примерно как в таблице. Расхождение больше 3 процентных пунктов нужно объяснить.
- **Сервер:** интеграционный тест в одном процессе — запустить сервер, подключить 2–4 клиента через `ws`, сыграть короткую партию по сценарию, проверить переподключение и что клиенту не пришла чужая рука.

Тесты проверяют правила, а не подгоняются под код. Реализация должна работать для всех допустимых ситуаций, а не только для тестовых. Если тест кажется неверным, сообщи пользователю, а не меняй тест молча.
