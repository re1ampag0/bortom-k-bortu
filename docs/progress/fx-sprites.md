Основа origin/main 28d9847, слитый fx-phone (#54). Ветка fx-sprites.
Только отрисовка/свет; engine, данные, правила не меняются.
Три этапа, commit/push в конце каждого. Проверки: typecheck каждый этап,
только новый hit-test и адресные e2e Армады по одному прогону; npm test один раз в конце 3.
Полный e2e, sim и дополнительные тесты не запускать.

## Этап 2 — сделано

- sprites.ts: DocumentFragment на каждый стол, один шаблон на тип и ограниченный пул
  готовых экземпляров. Создание HTML/SVG и уникализация gradient ID только при подготовке.
  takeSprite не парсит и не расширяет пул; SVG статичен, spriteA разрешает только transform/opacity
  HTML-обёрток. Повторные размеры не копят неиспользуемые типы.
- FxLayer готовит Армаду при открытии/resize вне клипа; типы ship/smoke-light/smoke-dark/ball/shadow.
  Пока Армада всё ещё рисуется старым способом. Шаблоны и свободные экземпляры НЕ вставлены
  в документ, не прозрачны и не стоят за краем экрана. Нет фонового RAF у кэша.
- Отмена/clear/reset возвращают временные экземпляры в пул и отменяют анимации.
  Пауза снимает will-change, продолжение восстанавливает только у живых анимаций;
  окончание снимает его, задержка не держит will-change заранее. Постоянные следы сохраняются.
- check-pool.mjs: 5 типов, 172 свободных экземпляра, 3186 DOM-узлов вне документа;
  connectedPrepared=false, после показа/паузы/отмены тот же пул, connected sprites=0,
  ни одной анимации на SVG. pool-check.json.
- measure.mjs: оптимизированная e2e-сборка, Chromium430×932/DPR3/CDP CPU×4,
  та же реальная сцена armada, ручной старт штатной кнопкой fixture, без вмешательства в engine.
  До: clip41784мс; Paint9991.077мс (максимум на главный кадр4002.742),
  Raster2688.521мс (максимум1899.403 между BeginMainThreadFrame),
  худший RAF6883мс, 101 интервал>50мс, пик1015 слоёв/1004 рисующих.
  Paint union по каждому потоку — вложенные Paint не суммируются дважды. Raster потоки
  суммируются отдельно от Paint; CPU-время не выдаётся за длительность GPU.
- Покоя два измерения по2с: до и с подготовкой одинаково26 слоёв/21 рисующий,
  Paint0мс, Raster0мс. Подготовка не добавляет работы в покое. before/prepared-metrics.json
  и сжатые исходные трассы рядом; кадр первой фазы armada-before.png снят отдельно от замера.
  Скрипт capture.mjs использует одинаковые native keyframes/управляемые часы/Math.random.
- npm run typecheck — exit0. npm test и e2e в этом этапе не запускались.

Дальше этап3: подключить наклейки к Армаде, сохранить траектории/числа/тайминги/порядок слоёв,
снять парный замер и кадр, выполнить адресные e2e Армады, typecheck и один npm test.
После этапа3 — остановиться до проверки iPhone; остальные эффекты пока не переводить.

## Этап 3 — сделано

- Армада: 4 корабля телефона/6 ноутбука, кильватер, качка, отдача — готовые SVG в HTML-обёртках.
  Отдельно двигаются ядро/тень, крупные клубы телефонного дыма. Контуры, координаты,
  random-последовательность выстрелов и значения T.armada сохранены. Мелкие следы/искры/
  брызги остаются сгруппированными в SVG. Туман горизонта и телефонная дымка тоже локальные SVG.
- Важное ограничение: дым ноутбука с общим feTurbulence/blur оставлен прежним SVG-групповым:
  разделение фильтра на отдельные облака меняет его рисунок. Телефонные дымовые клубы — наклейки,
  без новых фильтров и без растра. Прочие Залпы/потопления/Легенды не переводились.
- Отдача не анимирует filter: на ноутбуке opacity заранее осветлённой копии тех же контуров/градиентов;
  на телефоне новой белой вспышки корабля нет (A уже удалял brightness). Диагностические light/filters
  отключают эту накладку. Её дополнительная анимация не расходует прежний бюджет частиц.
- Кэш не расширяется в начале клипа, все новые типы подготовлены заранее. При редком несовпадении
  подготовленного размера используется исходный рендер; после resize в покое кэш обновляется.
  Для dev StrictMode исправлен повторный прогрев после cleanup. Замер после явно проверяет
  data-armada-renderer=stickers, чтобы не выдать legacy fallback за результат наклеек.
- Наблюдатель только за удалением прямых детей FX-хостов возвращает исчезнувшие следы/их детей
  в пул. Unmount отключает observer и очищает банк. Пауза/отмена/задержка повторно проверены
  своим check-pool: 8 типов, 191 свободный экземпляр, 3292 узла вне документа, active=0,
  connectedPrepared=false, никакой анимации SVG, после цикла пул полностью восстановлен.
- Кадр armada-before/after.png: первый огонь7620мс, снимок7720мс в обоих случаях,
  4 корабля/5 вспышек; после26 активных наклеек. armada-comparison.png — рядом.
  Это не побитовое равенство растеризации: 2886 пикселей (0.7201%) отличаются >6 RGB,
  armada-pixel-diff.json. Геометрия/фаза визуально сверены по сравнению; исходные SVG не перерисованы.
- Адресные e2e Армады 1366×660 и430×932 — 2 passed (37.3s), по одному прогону,
  существующие проверки отдачи/числа кораблей/отсутствия перекрытий/результата не менялись.
  Сгенерированные кадры прежнего отчёта восстановлены, новые — armada-e2e-*.png.
- npm run typecheck — exit0. npm test выполнен ОДИН раз: 60 файлов, 681/681 passed, 44.06s.
  Другие e2e, полный e2e, sim и дополнительные unit-прогоны не запускались.

## Итог и точка остановки

Этапы1–3 отправляются отдельными коммитами в fx-sprites. Дальше СТОП до записи с iPhone:
?perf=1,20с на Армаде; пользовательский критерий ≥50 кадров/с и ни одного кадра >100мс.
Потопление/обычный Залп/остальные Легенды и море, дальнейшие CPU-фризы и растр — не начинать.
Ноутбучный фильтрованный дым пока сохранён прежним; это оговорённое выше ограничение перевода.
