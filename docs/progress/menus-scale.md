# menus-scale

## База до масштабирования
Первый отдельный коммит: телефонные шрифты подготовки, расстановки, шторки и комнаты.
Подзаголовки15px; подписи13px/капитан12.5px; строки мест и описания14px; основные кнопки20px.
Компактные действия внутри места14px, как подписи строки, чтобы сохранять две кнопки рядом.
Кадры390×844 в screenshots/menus-all/, без изменения масштаба. Этот коммит — база «до» для Н2.
Проверки только в конце всей задачи.

## Реализация
- useMenuLayout — один источник режима/геометрии для фона, сцен и комнаты. Телефонная раскладка выбирается и для вертикального планшета; landscape667×375 трактуется как сцена, согласно списку пользовательских кадров.
- Игровая ветка scaleOf и её формула оставлены без изменений. Отдельная ветка useStage включается только активным меню. При k=1 и нулевом центрировании геометрические свойства stage не задаются, чтобы сохранить исходную отрисовку.
- CSS с viewport-условиями имеет точный прежний fallback для игры/menuscale=0 и ветку общего режима для включённого menus-scale. Исходная специфичность селекторов сохранена через :where.
- Единственное добавление DOM: пустой display:contents контейнер порталов рядом с MenuSurface, внутри #stage и атрибуты/класс режима корня. Существующие элементы, тексты, testid и их порядок не меняются. Окна игры используют прежнюю цель портала.
- PreparedScene получил только необязательный pixelRatio. Все прежние вызовы сохраняют прежний расчёт; menu-scene передаёт эффективный DPR при k≠1. Движение, часы и decode-кэш не переписывались.
- Нижняя панель закрепляется, только если её естественный нижний край не помещается над нижним отступом. Это сохраняет исходное положение уже видимых кнопок и не требует исключений по размерам.
- Пока фокус в поле и уменьшилась только высота viewport, геометрия удерживается. После закрытия клавиатуры используется фактический viewport.

## Сравнение
База:49f62b6 (отдельный первый коммит шрифтов), отдельный detached worktree. Во вспомогательных Vite-серверах одинаковая строка версии/дата, в браузерном прокси одинаковый код комнаты; сами игровые данные/сервер не изменены. Состояния одинаковые, scrollTop=0, существующий captureScene(0) замораживает подготовленные сцены, CSS/WAAPI часы ставятся на0мс. Различия считаются по декодированным пикселям PNG без допуска на цвет. На коротких экранах разрешена только динамическая нижняя полоса, вычисленная по прикреплённой панели, без маски остального экрана.

Нативные анимации PNG-снимка дополнительно отключаются штатным screenshot(animations:disabled); указатель убран в угол. Это исключает различия полупрозрачных фаз/hover, не меняя исходный код ни одной версии.

## Аудит и исправления

Снято200 кадров:25 размеров ×8 экранов,25 contact-sheet,48 кадров базы,48 выключенного режима и18 кадров клавиатуры. После исправлений эвристический скрипт не нашёл горизонтальной прокрутки, текста за горизонтальными краями, пересечения видимых текстовых блоков или ошибок страницы. Он исключает намеренно обрезанные прокручиваемые области и содержимое под модальным окном; это не доказательство отсутствия любого возможного пересечения.

Исправлены узкие сегменты Настроек, кнопки комнаты, переносы сохранённой партии на320px, переключение планшетной раскладки, прокрутка шторки и возврат после клавиатуры. Реальная прокрутка колёсиком: scrollTop67, кнопка594–648 при высоте664 (curtain-scroll.json). Сама шторка включает нативную прокрутку при первом жесте, если содержимое не помещается: исходный overflow:hidden до жеста сохранён ради точного Н2.

Все18 эмуляций клавиатуры сохраняют width/height/transform/left/top stage. Эмуляция уменьшает viewport на300px при фокусе; настоящий системный интерфейс клавиатуры не воспроизводится. WebKit executable отсутствует, установка не выполнялась, все кадры сняты Chromium с эмуляцией устройства. CDP safe-area здесь отсутствует: отдельно подставлены44px сверху и34px снизу через CSS-параметры, это явно отмечено в safe-area/result.json. Кнопка заканчивается на794px при экране844px:34px безопасной зоны +16px отступа.

Фрагменты текста и рамок сохранены в четырёх каталогах как text-and-border.png, сводный quality-text-and-borders.png показывает исходные пиксели с увеличением ×3 без сглаживания просмотрщиком:1366×660(k1),1280×600(k0.909),1920×969(k1.406),2560×1300(k1.874). Постоянное продвижение stage через will-change/translateZ не используется; поведение настоящего Safari при resize требует проверки пользователя.

## Решения

1. Приоритет Н2: исходные элементы, тексты и testid сохранены; добавлены атрибуты режима, класс menu-phone и пустой sibling-контейнер порталов. Вложение портала внутрь MenuSurface меняло наследование и растеризацию, поэтому контейнер размещён рядом, внутри общего stage.
2. Горизонтальный667×375 использует сцену, как требует перечень горизонтальных кадров, несмотря на неоднозначный порог700 в исходном описании А.
3. 11px для любого текста конфликтует с фиксированной1366px сценой и единым уменьшением: на667px коэффициент0.488 превращает исходные10px в4.88px. Даже база уже содержит подписи10px. Для соблюдения Н2 и одного масштаба отдельное увеличение шрифтов не введено. Предупреждения69 кадров сохранены, требование универсального минимума не заявляется выполненным.
4. Размер14px у поиска Правил ноутбука без фокуса сохранён для Н2; при фокусе и на телефоне16px. Крупные поля имени/кода не уменьшались до16px.
5. Меню используют прежний PreparedScene: добавлен только необязательный параметр плотности, без нового цикла анимации или переписывания часов/кэша. При k1 параметр не передаётся, если прежняя плотность уже в пределах нормы: это сохраняет точные пиксели.
6. E2e не правились. В просмотренных net/ui-press/phone сценариях прямых проверок координат нижней кнопки меню не найдено; прохождение всей существующей группы оставлено CI по условию задачи.
