## Шаг 1 — пять худших кадров в диагностике

perf/frames.ts ранжирует интервалы rAF и связывает каждый из пяти с ВСЕМИ
пересекающимися этапами/клипами, а не с последней меткой. В панель добавлена кнопка
«5 худших кадров»; тот же полный список всегда в «Скопировать числа». Нажатия
pointerdown/click/Enter/Space пассивно наблюдаются только при включённом perf;
предшествующее нажатие помечено отдельно (это не доказательство причинности). Края окна/подокна неполные, отмечены ≥:
это нижняя оценка интервала; прежний счётчик worstFrameMs — полные rAF-интервалы.

Метки JS: legendIntro создание, gunFire создание, вставка DOM/готовой наклейки,
renderWith и итог клипа, создание/размер/вставка canvas, прогрев пулов и smoke raster.
Визуальные интервалы legendIntro влёт/приземление/печать/удержание/шар и gunFire
планируются по тем же ctx.speed/T, без новых таймеров. Учитывается пауза очереди;
JS-операции помечены JS:, визуальная метка не означает работу процессора всё это время.
Ни T, ни RNG, ни элементы/рисунки/траектории не менялись.

Без perf панель не монтируется, nullable хуки выключены: нет чтения часов,
слушателей ввода и нового rAF. Используется существующий цикл счётчика показа.
Память меток ограничена4096; потерянные метки не скрываются. Публикация панели —
после показа, без рендеров Game на каждом кадре. Снимок профиля доступен измерителю
через импорт; глобального диагностического API в обычной сборке не добавлено.

## Шаг 2 — пять интервалов в трассе и проверка подготовки

Измеритель берёт снимки **тех же** пяти интервалов из perf/clip.ts, через
измерительный Vite-плагин. В обычной сборке глобальных window.fxFinish/счётчиков нет.
Вход Легенды — ограниченное подокно Армады; полный список Армады и Залпа проверен
на равенство списку «Последний клип». Для Кракена/Джека также сохранены профили.
Добавлены метки JS-кадра частиц и визуального сюжета LG, чтобы различать CPU-работу
и период, в котором эффект только виден. Все финальные dropped=0.

Ранний диагностический проход показал неразмеченные интервалы; он остановлен,
добавлены две метки и снята финальная серия всех шести сцен. Числа ниже — из неё.
После JS-этапа без активной метки показывается «после …», а не выдуманная текущая
операция. Нажатие непосредственно перед началом окна (не более1с) помечено
«перед показом»: это наблюдение, не доказательство причинной связи с запуском.

Привязка к трассе — по одному performance.mark cpu-start и его performance-clock
startTime, без смешивания часов Node/браузера. События, начавшиеся ДО кадра,
обрезаются по обеим границам. Стоимость каждой категории — union вложенных
интервалов, Style/Layout/Paint/Layerize вычтены из Scripting. DOM-колонка — wall-time
помеченных операций создания/вставки, уже входящий в категории; её не суммировать
с ними. Layerize/UpdateLayerTree показывают CPU-работу композиции, а не точное
число новых выделений слоёв; allocatedLayers=null, число не выдумывается.
Raster по рабочим потокам сохранён отдельно в JSON; GPU-время им не подменяется.
Остаток wall-time может быть ожиданием/планированием ОС/GPU — это не «чистый JS».
