# ship-window

Ветка ship-window, основание origin/main b59cd7d (PR #74). Прочитаны CLAUDE.md,
UI/animation RULES.md, PORTING.md, README/NOTES макета; пять досок открыты.
Все 14 файлов assets на месте, фраза NOTES «картинок нет» устарела.
Для просмотра сервер должен обслуживать родительскую папку ship-window,
чтобы относительные ../assets разрешались; vendor/support в игру не перенесены.

## Этап 1 — каркас и тело

Новый отдельный ShipWindow в портале вне масштабируемого стола. На ноутбуке
920×640; ширина/высота окна учитываются одним коэффициентом (resize/visualViewport)
через CSS-переменную ближайшего контейнера, без setState/повторной раскладки.
Кнопки ×, Esc и фон закрывают окно; Сброс открывает прежний DiscardSheet.
Game передаёт только fx.store. Окно подписано на показанное состояние: шкалы,
Души/Легенда не опережают клип; анимационный clock не рендерит Game.
Тексты особенностей/Легенды, девиз, капитан, шкалы, Рука/Колода/Сброс/Планы —
данные игры, не числа/копии текста макета. Текст в игре местами длиннее макета;
это намеренное отличие данных, оформление не подгоняли заменой правил.
Души: число из показанного состояния, два пояснения череп → Корпус/Команда +1;
это подписи обмена, не новые кнопки игровых действий.

Тело окна, значки и неподвижная заготовка сцены извлечены из принятого макета
scripts/ship-window/extract.mjs. Они показываются как img; ни runtime холста,
ни крупные анимируемые SVG в окно не вставляются. decode до показа, заранее
при открытии стола. Живое движение сцены/медалей ещё НЕ сделано (этап 2).
Телефон сейчас ещё НЕ готов (этап 3), щупальца ещё НЕ менялись (этап 4).

Проверка этапа: npm run typecheck прошёл. Короткий capture.mjs снял 8 состояний:
4 корабля × 1366×660/1920×944; ошибок страницы и обрезания окна нет.
Кадры: docs/screenshots/ship-window/stage1/*-{game,window,mockup,comparison}.png,
числа/геометрия: stage1/proof.json. На 1366×660 окно 920×640 целиком внутри экрана.
У сравнений одинаковые локальные игровые шрифты; иначе внешние шрифты макета
в облаке могли подменяться fallback и давать неверную разницу ширины табличек.
Ни e2e, ни npm test на этапе 1 не запускались. Скорость/остановка сцен пока
не заявлены: замеры и строгие проверки следуют после реализации этапов 2–4.

Точка продолжения: этап 2 — разложить четыре сцены на заранее подготовленные
слои/кадры, добавить медальоны и жизненный цикл паузы. Сохранить готовую вёрстку.

## Этап 2 — четыре живые сцены

Сцены экспортированы из принятых досок scripts/ship-window/scenes.mjs:
неизменяемые рисунки декодируются до включения сцены, двигаются HTML-обёртки
(transform/opacity). Фильтры дальних кораблей и маски отражений запечены в PNG,
живых SVG-фильтров/масок нет. Огонь и перелив — четыре исходных кадра;
мелкие звёзды/искры/брызги — два холста по уровням, на телефоне половина.
Медаль Легенды: неподвижная картинка и отдельный блик; особенности: четыре
подготовленных кадра исходного SVG. Раскадровка сохраняет исходные периоды.
Декодированные изображения удерживаются для одной активной сцены, не всех четырёх.
Пауза: скрытая вкладка, IntersectionObserver, клип стола, reduced motion;
при закрытии отменяются native-анимации, rAF и подписки, узлы удаляются.

npm run typecheck — прошёл (ship-stage2-typecheck.log). Сравнения с макетом:
stage2/ (фаза 0), stage2-motion/ (3000 мс), все четыре корабля на обоих ноутбуках.
В capture исправлена среда шрифтов: внешний каталог node_modules должен быть
в allow list локального Vite; иначе проверка снимала fallback вместо Alegreya.
Тексты/значения игры отличаются от демонстрационных данных досок намеренно.
Телефон, замер Paint/Layout, e2e и финальные unit-проверки ещё впереди.
Точка продолжения: этап 3 — полноэкранный телефон по доске Phone.

## Этап 3 — телефон

Полноэкранный лист с вертикальным скроллом по Phone: сцена, табличка,
девиз, четыре строки шкал (и Души), особенности, Легенда, счётчики/Сброс.
Карты/шрифты не уменьшаются вместе с ноутбучным окном. Ряд счётчиков листается,
кнопки не сжимаются. Resize/visualViewport меняет только локальные CSS-переменные;
при смене телефонного порога перестраивается только ShipScene, не Game.
Для Голландца отдельно извлечена сцена Phone 390×196 и фон тела: те же
положения объектов и периоды. Для остальных трёх (отдельных телефонных досок
для них нет) — видовая область панорамы с кораблём в центре, тело по Phone.
Телефонные частицы: половина, DPR холста не выше2, без mix-blend.
Изображения сцены и фон декодируются до открытия содержимого.

npm run typecheck — прошёл. stage3/proof.json: 12 кадров/состояний без
обрезания рамки и ошибок страницы; 4 корабля × два ноутбука и430×740.
*-game.png — верх реального экрана; *-bottom.png — низ при прокрутке;
*-window/comparison.png — весь лист рядом с Phone (демо390, игра430).
Диагностическая табличка выключена для чистых кадров; perf=1 проверяется отдельно.
Следующий этап: точные щупальца из макета, затем адресные проверки и замеры.
