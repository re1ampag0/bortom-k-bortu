## Решения и границы подтверждения

- Файлы макетов находятся прямо в `docs/mockups/2026-10-26/`, без каталога img. В сравнении использованы эти исходные JPG. Для25–28 нет отдельного утверждённого кадра в тексте задания: слева общий кадр стола `wide-after2.jpg`; для них важнее реализация и отдельные кадры/данные, чем буквальное совпадение общего фона.
- Пункт11: протокол предоставляет `seats.online` и существующую замену ботом, но не предоставляет команду общей серверной паузы. Она **не реализована**, протокол не расширялся. Окно честно сообщает об ожидании капитана, даёт подождать/заменить. При возвращении друга окно остаётся до действия пользователя. Кадры сняты реальным подключением двух браузерных клиентов и закрытием одного.
- На коротком телефоне просвет моря слишком мал для полной236px таблички по высоте. Она не выходит на планшеты: первая строка показывает «Залп» и урон; остальные сведения доступны прокруткой внутри. На просторном экране виден полный вариант. Подсказки, нажатия строк карт, отмена/перенаправление и след используют прежний механизм; правила и длительности не менялись.
- Убран ранний свет у дул: первый кадр glow/cone непрозрачен только после начала анимации (появление занимает менее1мс прежней длительности); во время задержки opacity0. Вспышка привязана к реальному дулу клетки Пушек, для отсутствующих клеток оставлен прежний запасной путь. `T.*` не менялись. Остаточный долгий дым в море сохраняется, короткий дым над планшетом использует прежний smokeOver.
- Hover: внешняя кнопка и её зона стоят, внутренний рисунок движется transform. [Данные геометрии](../screenshots/ui-polish/details.json), [остальные размеры](../screenshots/ui-polish/details-remaining.json). Дрожание зоны не воспроизводилось: прямоугольник кнопки до/после совпал.
- Сцена молнии без парусов снята собственным **рендер-сценарием**: копия эталонной sea-thunder со стартовыми Парусами0 и без событий повреждения Парусов. Подмена только в ответе dev-сервера скрипту кадров; файлы данных и движок не изменены. Это доказательство вида нужной ветви рендера, не отдельная проверка правил.
- Скрипт кадров снимает интерфейс dev-сборки с единственным монтированием React, как в production: capture-only подмена StrictMode→Fragment обходит известное двойное закрытие сетевого клиента в dev. Файл main.tsx для этой цели не менялся.
- На телефоне рука по прежнему открывает поднятую карту, а не CardDetail. Для показа самого общего окна карты скрипт вызывает существующий onCard обработчик Hand через React fiber; это только подготовка кадра. Логику касания/выбора руки не менял.
- Полный свод скрывает технический раздел21 о сверке sim.py и служебное введение только при отображении; исходный RULES.md сохранён. Игровые разделы1–20 остаются.
- Служебные слова в комментариях, идентификаторах, кодах карт, именах файлов и отладочных трассах не переводились. Display-only обработка не переписывает журнал/данные на диске.
- Кадры подтверждают вид в Chromium; реальный WebKit/телефон здесь не проверялся. Готовность CI и отсутствие всех возможных e2e-регрессий не заявляю.

## Воспроизведение кадров

Существующий dev/e2e Vite-сервер с прокси локальной сети: порт5405; локальный сервер5404, отдельный временный каталог комнат. Зависимости используются из соседнего установленного рабочего дерева; симлинк node_modules не входит в коммит.

- `scripts/ui-polish/fixtures.ts`: существующие легальные записи середины партии + поиск реального pending Tortuga, без изменения правил.
- `scripts/ui-polish/capture.mjs`: экраны/диалоги; фильтры SCENES и SIZES для пересъёмки только изменённых.
- `scripts/ui-polish/extra.mjs`: разбор, погода/молния, отсчёт и выход друга. ONLY=plate или ending-friend ограничивает пересъёмку.
- `scripts/ui-polish/details.mjs`: кадры выстрелов и геометрия hover.
- `scripts/ui-polish/compare.py`: склейки с исходными макетами.

Это скрипты пользовательских кадров, не новые тесты. Первые кадры с ошибкой доступа к шрифтам403 были заменены после исправления fs.allow локального стенда. Итоговые кадры и склейки находятся в screenshots/ui-polish.
