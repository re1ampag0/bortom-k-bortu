docs/mockups/2026-10-26/card-art/ — 81 готовая картинка (WebP 600×360, по одной на каждое уникальное имя карты во всех
четырёх колодах; карты с одним именем в разных колодах — одна картинка) и manifest.json:
{ "<имя карты как в data/game-data.json>": { "file": "<slug>.webp", "type": "ЗАРЯД|ПРИКАЗ|РЕМОНТ|РЕАКЦИЯ", "decks": [...] } }.
Рамка цвета типа карты и уголки уже нарисованы внутри картинки. Картинки утверждены пользователем, не перерисовывать
и не пережимать заметно (допустимо пересохранить WebP q 80–85, если так меньше).
Макеты вида карт: img/deck10-pearl.jpg, img/deck10-revenge.jpg, img/deck10-endeavour.jpg, img/deck10-dutchman.jpg

ЧТО СДЕЛАТЬ
1. Положить картинки в src/ui/art/cards/ (или другое место сборки по твоему решению) так, чтобы у них были хешированные
   имена и кеш immutable; карта → картинка по manifest.json (по имени карты). Грузить лениво: картинка карты
   запрашивается, когда карта впервые появляется на экране (рука, Коллекция, окно), с decode до показа; пока не
   готова — пергаментная заглушка того же размера (без прыжка раскладки). В начале партии в простое подогреть
   картинки своей колоды по одной (requestIdleCallback), не на медленной сети (saveData, 2g/3g).
2. Рука (Hand.tsx, .hcard), ноутбук и телефон — вариант А, макеты img/g16-hand.jpg (ноутбук), img/g16-hand-phone.jpg
   (телефон); CSS — reference/hand.css (классы .cm.vA). Сверху вниз, всё по центру одной оси:
   - шапка 16 px (ниже прежней): тип по центру всей ширины (Alegreya Sans 700, 8 px, разрядка .18em), цена — латунная
     плашка 13 px справа (right 3 px), не сдвигает тип;
   - картинка во всю ширину карты и ЦЕЛИКОМ, без обрезки: пропорция 200/120 (как у самой картинки 600×360),
     object-fit: contain / без кадрирования; ничего из сцены не срезается;
   - высота мини-карты: ноутбук 168 px (было 146; карта растёт вверх, низ ряда руки на прежнем месте, зона руки
     и стол не сдвигаются; если сверху не хватает места до трюма/моря — уменьшить шрифт описания, но не картинку),
     телефон — прежняя (112×160);
   - название: Alegreya SC 700, ноутбук 11 px, телефон 11,5 px, тёмное #1e1408; место всегда на две строки (height 2.12em),
     текст по центру по вертикали — у всех карт следующие строки начинаются на одной высоте; без обрезки и многоточия;
   - плашка big: Alegreya Sans 700, 9 px, цвет типа, по центру, может переноситься;
   - описание (текст правил): Alegreya 9 px (ноутбук) / 9,5 px (телефон), строка 1.2, по центру, на всю оставшуюся
     высоту целыми строками (как сейчас useWholeLines + line-clamp), последняя строка с многоточием, обрезанных
     пополам строк нет.
   Бумага — светлая слоновая кость (radial-gradient #fffdf8 → #f7f2e6 → #ebe2cf), не жёлтая; кант тонкий латунный
   #b8964a. Отступы одинаковые у всех карт: 4/3/3/3 px между блоками, 6–7 px по бокам, 5 px снизу.
   Белая рамка убрана. Чтобы название не пряталось под соседней картой, карты в руке меньше заходят друг на друга
   (ноутбук перекрытие ~16 px вместо 30, телефон ~6 px). Состояния off, chosen, plan, alarm/strip, lift — работают
   как сейчас, поверх нового вида. «План» (рубашка) — без картинки, как сейчас.
3. Поднятая карта (lift, img/g14-lift-phone.jpg): первое нажатие на телефоне поднимает карту, в ней — картинка,
   название, плашка big и ПОЛНЫЙ текст правил по центру (Alegreya 11 px), под картой «Сыграть» (красная доска) и
   «Продать», «Передать» тёмными с латунью. Высота поднятой карты по содержимому, ничего не обрезано. Окно карты
   (ui-polish пункт 2) — та же картинка над названием, размер по ширине карты.
4. Коллекция (Catalog.tsx / CardView.tsx, оформление из ui-polish пункт 7): полная карта как в deck10-*.jpg —
   шапка (тип, цена), картинка, название, разделитель-ромб, плашка big, текст правил по центру, курсив flavor,
   подпись корабля внизу пунктирной линией. Размер текста зависит от длины (как в reference/card.css: .l, .xl),
